# Firehose replay demo

This page compares recordings from the actual Firehose/Cell2Fire simulator.
The neural policy uses a saved checkpoint. The browser does not train the network
or simulate another wildfire; it displays the generated episode frames.

From the project directory:

```bash
.venv/bin/python -m http.server 8766 --bind 127.0.0.1 --directory firehose_demo
```

Open http://127.0.0.1:8766. Stop the server with Ctrl+C.
`data.json` must first be generated by the project's Firehose runner. If it is
missing, the page states that clearly; it never displays invented fire behaviour.
A generated offline HTML file can also embed the same recordings through
`window.FIREHOSE_DATA` and run without a server.

1. Choose **Sub20x20** or **Sub40x40** in **Map / neural checkpoint**, then a recorded seed.
2. Choose a comparison policy. Only recordings with the same seed and map appear.
3. Press **Next step** to see one decision interval, or **Play** for playback.
4. The outlined cell is the action applied to reach the current frame.
5. Compare fire-affected cells, treated cells and cumulative return. Expand the full
   trajectory to inspect every action or the outcomes table to see all recordings.

**Seed** identifies the scenario's random choices. Changing it selects another
saved episode. It does not retrain the policy. **Episode** means one wildfire run.
**Interval** is one policy action and its configured number of Cell2Fire physics
steps; the timing is shown under the explanation/details. **Checkpoint** means
saved neural-network parameters. Its exact name, available training-step count
and hash are shown under **Checkpoint and simulator details**.

Firehose treatment permanently protects a cell and extinguishes it when burning.
Blue cells are treated, red cells are fire-affected (the original exported state combines burning and burned), and the pink cell marks ignition.
Vegetation colours vary by type. A connected barrier must emerge from successive
cell actions. The simulator does not automatically complete a perimeter.

The two policies may finish at different intervals. The earlier episode remains
on its final frame. A final frame can indicate extinction or a time/weather limit;
read its status rather than assuming every ending means containment.

The outcomes table presents individual saved episodes, not a population-wide
performance claim. The original exported state does not give a verified active-fire count. Read
fire-affected counts together with reward and treatment counts, rather than
interpreting every red cell as actively burning.

## Files

- `index.html`, `styles.css`, `app.js`: local replay UI.
- `data.json`: real recorded episodes and provenance, generated separately.
- `check_browser.py`: optional browser check against a running server.

Run the check after generating recordings and starting the server:

```bash
.venv/bin/python firehose_demo/check_browser.py
```

It requires the workspace's optional Playwright/Chromium installation.
